# SerialHub 领域术语表

本文件是 SerialHub 的统一语言（Ubiquitous Language）。仅收录概念定义，不含实现细节。

## 术语

### 主实例（Master）

先启动的 SerialHub 进程，持有本侧串口，对外提供完整服务面（MCP、xterm web 终端、健康检查）。联邦中的唯一调度者：聚合双侧串口、把操作路由到正确的侧。

### 从实例（Worker）

在已存在主实例时后启动的 SerialHub 进程。前台运行，不提供 web 终端；职责是贡献本侧串口（上报端口、受主实例调度读写）并在本侧反代 MCP 端点。Ctrl+C 退出即脱离联邦。

### 联邦（Federation）

主实例与从实例组成的协作关系。联邦成立后，主实例的串口列表聚合双侧端口，任何一侧的 MCP 客户端都能操作另一侧的串口。

### 发现（Discovery）

进程启动时判定自身角色的过程：探测本机 5000 端口（WSL 下加探 Windows 网关地址）——探到主实例则成为从实例，探不到则成为主实例。

### 晋升（Promotion）

主实例失联后，从实例经过重连确认，自动升格为主实例、接管服务端口的过程。联邦语义为「谁活着谁是主」。

### 双通道（Dual Channel）

主实例同时服务的两条访问通道：**MCP 通道**（AI 的请求式操作接口）与 **xterm.js 通道**（人的实时终端）。两条通道共享同一串口连接与数据流。

### 数据桥（Data Bridge）

把串口数据同时分发给 web 终端显示与 MCP 读缓冲的内部机制。联邦端口的数据由从实例上行至主实例后进入同一分发路径。

### 本地启动（Local / stdio）

MCP 客户端（如 OpenCode）以子进程方式拉起 SerialHub 并通过 stdio 通信的接入方式。子进程发现主实例时退化为透明代理。

### 远程接入（Remote / HTTP）

MCP 客户端通过 HTTP 端点（`http://127.0.0.1:5000/mcp`）访问已运行 SerialHub 的接入方式。铁律：永远写 `127.0.0.1`，联邦模式下从实例会在本侧反代到主。

### 串口侧（Side）

串口设备所在的操作系统环境：`windows` 或 `wsl`。联邦端口的标识为 `side:port`（如 `windows:COM3`）。

### 透明代理（Stdio Proxy）

本地启动的子进程在发现主实例后的形态：不碰硬件、不起监听，仅在 stdio 与主实例 HTTP 端点之间转发 MCP 消息。
