# SerialHub 领域术语表

本文件是 SerialHub 的统一语言（Ubiquitous Language）。仅收录概念定义，不含实现细节。

## 术语

### 主实例（Master）

对外提供完整服务面（MCP、xterm web 终端、健康检查）的 SerialHub 进程，持有本侧串口。同一配置/安装作用域内同时只允许一个主实例（见「单实例锁」）。

### 单实例锁（Instance Lock）

保证配置/安装作用域内唯一主实例的机制：主实例持有 OS 文件锁；常驻的 lock 文件记录地址及 PID 供发现，进程退出即由内核释放锁。已有持有者时拒绝再次启动（或由 stdio 模式代理）。

### 双通道（Dual Channel）

主实例同时服务的两条访问通道：**MCP 通道**（AI 的请求式操作接口）与 **xterm.js 通道**（人的实时终端）。两条通道共享同一串口连接与数据流。

### 数据桥（Data Bridge）

把串口数据同时分发给 web 终端显示与 MCP 读缓冲的内部机制。

### 本地启动（Local / stdio）

MCP 客户端（如 OpenCode）以子进程方式拉起 SerialHub 并通过 stdio 通信的接入方式，也是 `serialhub setup` 的默认接入模式。子进程发现主实例时退化为透明代理；无主实例时自成主实例（起监听、提供完整服务面）。

### 远程接入（Remote / HTTP）

MCP 客户端通过 HTTP 端点（`http://127.0.0.1:5050/mcp`）访问已运行 SerialHub 的接入方式。铁律：永远写 `127.0.0.1`，除非访问局域网其他机器上的实例。

### 串口侧（Side）

串口设备所在的操作系统环境：`windows` 或 `wsl`。`serial_list` 的 `side` 字段标识每个端口所在侧。

### 透明代理（Stdio Proxy）

本地启动的子进程在发现主实例后的形态：不碰硬件、不起监听，仅在 stdio 与主实例 HTTP 端点之间转发 MCP 消息。

### 脚本（Script）

一次有界的串口交互剧本：由若干**定时写**与**匹配写**组成，在限定时长内执行，结束后返回触发记录与期间收到的数据。同一时刻至多运行一个脚本；剧本跑完、超时、断连或被取消即终止。

### 定时写（Timed Write）

脚本中按计划自动发送的数据条目：以相对脚本启动的时刻（单次）或固定周期（重复）触发，与接收内容无关。

### 匹配写（Match Write）

脚本中与接收数据内容联动的数据条目：当启动后新到达的数据匹配到指定模式（正则）时自动发送。默认命中一次即失效；可声明为持续生效，并可限定最大触发次数，耗尽即失效。多条规则按声明顺序独立评估。触发（命中）与发送可分离：命中即记录并计数，可配置延时（默认 5ms，显式 0 为立即）后再写出；延时未到即遇超时或中止则丢弃不发。

### 数据内容日志（Data Log）

包含串口或通道数据内容的日志，区别于只记录连接、断开、错误等状态变化的**事件日志**。默认关闭，可显式开启；内容以转义形式展示，并进行聚合与截断，避免刷屏。
